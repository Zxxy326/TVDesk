# TVDesk 1.1.6

版本：1.1.6（versionCode 17）
日期：2026-11-05

主题：**桌面守护失效的修复**，以及收藏、搜索、提示条三处体验补完。

---

## 一、桌面守护失效（重大问题）

### 现象

按遥控器 HOME 键直接回到固件桌面（`com.mitv.tvhome`），TVDesk 完全不拦。

### 根因

查现场状态，两个值对不上：

```
enabled_accessibility_services = com.tvdesk.app/…/HomeGuardService   ← 名字还在
accessibility_enabled          = 0                                   ← 总开关被关了
dumpsys accessibility: Bound services {}   Crashed services {HomeGuardService}
```

系统在服务崩溃一次、或待机清理一次之后，会把无障碍**总开关**改成 0，但启用列表里
仍然留着服务名。而 `GuardSetup.ensureEnabled()` 当时只判「名字在不在」——在就直接
`return true`，于是总开关永远补不回来，服务从来没绑上，HOME 自然没人接。

同一个盲点还在三处：复活闹钟（`ReviveAlarmReceiver`）、设置页状态、`describe()`。

### 修法

- `GuardSetup` 新增 `accessibilityEnabled()` / `isGuardReady()`（名字 + 总开关）/
  `isBound()`（`AccessibilityManager`）。
- `ensureEnabled()` 现在两样都判；总开关被关过时，把自己从列表里摘掉再加回去
  （逼系统重新绑定），最后写回 `ACCESSIBILITY_ENABLED = 1`。
- `HomeGuardService.onKeyEvent` 不再用 `HomeRole.isDefault` 放行。这台固件**即使
  HOME 的 role 给了我们**，按键仍会拉起 `mitv.tvhome`；放行等于「回系统桌面再靠
  窗口事件弹回来」，中间那一下是看得见的。
- `DeskActivity` 加守护看门狗：运行期间每 60 秒复核，掉线自动补。
- `BootReceiver` 开机 / 覆盖安装（`MY_PACKAGE_REPLACED`）时先补守护。
  —— 1.1.5 → 1.1.6 这次升级，系统正是这么把开关关掉的。
- 设置页与复活闹钟改用 `isGuardReady()`，掉线时显示「已掉线 · 按确定修复」。

### 实测

把 `accessibility_enabled` 手动置 0 → 65 秒内看门狗写回 1 并重新绑定 →
按 HOME，0.5 秒内回到 TVDesk。

## 二、详情页收藏按钮

以前收藏只挂在首页 Hero 那颗 ♥ 上，从搜索 / 收藏 / 历史点进详情页反而收不了。

- 播放键右边新增「收藏」，与首页那颗 ♥ 共用 `VodFavorites` 清单，两边状态实时一致；
  已收藏显示「★ 已收藏」+ 琥珀色，取消即恢复。
- `VodFavorites` 判重补一条**片名兜底**：首页豆瓣条目没有 `sourceKey/id`，
  从详情页再收一次不会在清单里多出一条。
- `DetailPage.Host` 新增 `favoriteChanged()`：宿主收到后重铺收藏墙，
  否则详情里收完退回收藏页还是「还没有收藏」。

## 三、搜索问遍全部源

`DetailFeed` 里写死了 `MAX_SEARCH_SOURCES = 18`。而配置里几十个站，前 18 个绝大多数
是 `type=3` 的网盘爬虫，搜一部普通影视时 17 个返回空——看起来就像「只有一个源有这部片」。

| 项 | 以前 | 现在 |
|---|---|---|
| 参与搜索的源 | 18 | **64** |
| 并发线程 | 4 | 8 |
| 总预算 | 15s | 22s |

实测「嫁金钗」：日志从 `参与 18 个源` 变成 `参与 64 个源`，虎斑 / 玩偶 / 木偶 / 花卷 /
剧透 / 文才 / 闪电 / 瓜子… 都回来了。

结果卡标注也修对了：以前**只有备注为空才显示源名**，而网盘源几乎都带「4K正式版」
这类备注，一屏看过去分不清哪张来自哪站。现在固定显示「源名 · 备注」。

> 说明：`type=3` 那批网盘爬虫对普通影视仍然大多「无结果」，那是站点能力问题
> （它们只索引网盘链接），不是这一版能解决的；但至少现在它们都会被问到。

## 四、搜索页布局

- **键盘收窄**：左列 560dp → 430dp；键高 42 → 34dp，行距 8 → 5dp，
  操作行 40 → 36dp，字号 16 → 15sp。键盘是输入工具不是内容，之前占掉半屏。
- **结果区多一列**：`GRID_COLUMNS` 4 → 5，让出来的宽度用来多放一列。
- **默认焦点进片名框**：`pushPage` 之后立刻 `requestFocus` 会落空（页面还没量完，
  系统随后按「第一个可聚焦」把焦点补给键盘的 A）。改成等 `OnGlobalLayout` 之后再要，
  并在 220ms 补一次；拿到焦点立刻 `hideIme()`（420ms 再补一次），
  否则电视上焦点进输入框会自己弹系统输入法盖住下半屏。
- **最近搜索挪到键盘正下方**，两列排布、最多 6 条、超出省略号截断；
  条目用 `bg_module_item`（平时透明，聚焦时白描边 + 亮底）。
- **焦点框不再被裁**：每行 `LinearLayout` 默认 `clipChildren=true`，把 1.06 倍放大
  的那一圈切平了 → 关掉；外层左列为了挡溢出保留裁剪，所以给历史容器四周留 8dp
  让出放大余量。

## 五、底部提示条统一

系统 Toast 在这台电视上是直角浅灰实底，压在全屏画面上像一块硬白方块，样式由系统定、改不了。
App `targetSdk` 还是 28，`Toast.setView` 仍然有效，于是自绘一个：

- 新增 `core/DeskToast`：圆角 20dp、纵向微渐变半透明深色（`#E622232B → #D9181921`）、
  1dp 12% 白描边、15sp 字、最多两行、离底 96dp（避开过扫区与播放条）。
- 全仓 31 个文件里的 `Toast.makeText` 统一换成 `DeskToast.makeText`（签名一致，
  调用方结构不动）。
- 播放器中间的「正在获取播放信息」「正在解析播放地址」也换成同一套磨砂底
  （`bg_player_tip`），以前只有一行白字压在亮画面上，遇到亮场景基本看不清。

> 说明：内容源（爬虫）自己弹的提示——例如「本接口免费分享！切勿上当！」
> 「正在搜索弹幕」——是远端蜘蛛代码直接调系统 Toast 弹的，代码不在本仓库，
> 样式无法改写。已确认这些文案在 APK、配置、内置 js、本地 jar 里都不存在。

## 升级说明

- 覆盖安装即可，无需先卸载；配置、收藏、播放记录都保留。
- 升级完成后请按一次 HOME 键确认：应当回到 TVDesk 桌面。
- 若此前守护处于「已掉线」，进入设置页该行会显示提示，按确定即可修复；
  正常情况下看门狗会在 1 分钟内自动补回。
