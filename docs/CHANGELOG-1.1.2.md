# TVDesk 1.1.2

版本：1.1.2（versionCode 13）
日期：2026-11-02

主题：**查清「唤醒后停在原生桌面」的真正原因**（不是开机自启失败）。

## 关键事实：那次不是重启，是待机

```
adb shell cat /proc/uptime
105751.34 ...          → 系统已连续运行 1 天 5 小时
```

遥控器「关机」在这台电视上是**待机**（关屏，系统不重启）。所以之前所有关于
「开机自启」的推理都不成立 —— 真正要修的是**待机唤醒**。

## 实测到的系统行为（MiTV-MFTR0 / Android 14）

待机 20–25 秒后：

| 检查项 | 结果 |
| --- | --- |
| `ps -A | grep tvdesk` | **0**（进程被杀） |
| `dumpsys package … stopped=` | **true**（force-stop 级） |
| `enabled_accessibility_services` | **null**（无障碍绑定被清空） |
| `enabled_notification_listeners` | 只剩云盘那条（**我们的复活监听被移除**） |
| `dumpsys alarm` 里本应用的闹钟 | **0 条**（全被取消） |

也就是说系统在待机时对第三方桌面执行了 force-stop，并**撤销了全部授权**。
`force-stop` 之后应用的闹钟会被取消、隐式广播收不到 —— 应用层能想到的自救手段
（闹钟、广播、服务）在这台固件上都会被一并清掉。

## 本轮做了什么

1. **BootReceiver 去掉 `isDefault` 门槛**（1.1.1）：小米永远不给第三方桌面 HOME 身份，
   这个门槛让开机一次都没拉过；
2. **守护服务连接后 3s/8s/15s 复查前台**（1.1.1），并新增「拉起后 1.2s / 6s 复查，
   被原生桌面抢回就再拉」——Aerial 在 MiTV 上就是这么处理的；
3. **复活监听 `RevivalListener`**（通知监听）：系统重新绑定时恢复无障碍绑定、必要时拉起桌面。
   不读通知内容；
4. **定时复活闹钟**（1 分钟）：进程被杀后由系统闹钟补一次；判据是「无障碍绑定是否丢失」，
   而不是「黑屏/亮屏」，正常使用时绝不触发。

## 仍然无解的部分（诚实记录）

force-stop 之后，上面 3、4 两条也会被系统取消。这是平台的硬约束，
应用层没有绕过手段。真机实测：待机唤醒后 100 秒内闹钟、通知监听都没被触发。

能改变这一点的只有系统侧：

- 在电视管家/系统设置里给 TVDesk 开「自启动」或「后台运行」白名单；
- 或者把 TVDesk 设为默认桌面（这台固件把 HOME 锁在自家桌面，
  `cmd package set-home-activity` 返回 Success、role 也归了我们，但按 HOME 仍去 mitv）。

## 已验证

- 覆盖安装后自动拉起；`stopped=false`
- 无障碍绑定、通知监听授权都能在应用启动时自动写回
- HOME 键接管正常（`HomeGuard: 接管 HOME：从 com.mitv.tvhome 回到桌面`）
