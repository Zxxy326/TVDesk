版本：1.1.5（versionCode 16）

主题：**把日常用起来别扭的地方集中修一遍** —— 播放、选集、搜索、返回键、弹幕、筛选、音源市场。

## 一、播放器

### 1. 音乐播放页切歌，画面和提示都停在上一首

`nowPlaying` 原来要等播放器真正开始播才更新。在线歌要先让音源脚本换直链，
这几十秒里标题、封面、歌词、进度全是上一首的 —— 声音切了、画面没切。

现在：

- `play()` 一开始就把 `nowPlaying` 指向新歌，界面立刻刷一遍；
- 状态行（「已切换到 xx」/「解析失败」）每首歌开播先清掉，取链接期间显示「正在取播放链接…」；
- 换歌先清歌词（显示「正在取歌词…」），进度归零；
- 新增 `playerTrack`（播放器里实际装的是哪一首），进度同步 / 暂停 / 单曲重播都按它判断，
  换歌期间不会误读上一首的位置。

### 2. 起播失败自动换源

`MediaPlayer.onError` 是异步的，`startPlayer` 早就返回成功，以前只能写一句「这一首放不出来」。
现在把「哪一首、哪个源」交给 `handlePlaybackFailure()`：

```
起播失败 → 删掉这条死链的缓存 → 换一个源重试（最多 2 个）→ 还不行自动下一首
                                                              → 连续 2 首都这样才停手
```

必须删缓存：解析器读缓存时第一个 key 就是 `auto`，不删的话下一轮会把同一条死链原样拿回来，
「换源」等于没换。

### 3. 控制区收起后焦点跑丢

控制区 6 秒自动淡出后焦点挂在整层播放页上，按方向键会按几何关系跑到被盖住的「正在播放」胶囊，
屏幕上看不到焦点框、按确定也没反应。现在收起状态下任意键先唤回控制区，五个按钮显式指定左右邻居。

## 二、影视

### 1. 续播：按集名认集

旧实现把「第几集」当数字直接盖到当前线路上。实测同一部剧不同线路的排序不一样
（这条线第 39 条是 E20，那条线第 21 条才是 E20），于是「记住的是别的集」。

- 读续播点时先按**集名**在当前线路里找下标，找不到才退回数字；
- 播放器 `play()` 里写续播点：以前只在详情页按「播放」那一刻写，在播放器里换集后退出就丢了；
- 每 10 秒 + 退出/切后台落一次「这一集看到第几秒」；
- 源站换过 id 时按片名兜底；跨源命中但集名对不上时**不猜**。

### 2. 选集一屏放得下

- 一段 = 列数 × 3 行，翻段就能看到全部集数，不用一路按下去滚；
- 每一格单独挂 `OnKeyListener`（父容器收不到方向键）；
- 当前集用 `activated` 状态 + 琥珀色描边，不被 GridView 自己抢的 `selected` 盖掉。

### 3. 点播强制 SurfaceView

TextureView 每帧走 GPU 合成，弱 GPU 播 4K 丢帧严重。实测日志：

```
SurfaceView：onDroppedVideoFrames 累计 0
TextureView：每秒约 17 帧
```

### 4. 筛选真正生效

三个断点一起修：

1. CMS 源请求里根本没带筛选参数（只发了 ac/t/pg）→ 补 `filterSelect` 平铺 + `f=JSON`；
2. 首屏缓存 key 只有 `sort.id`，勾完筛选命中旧缓存 → key 带上筛选条件；
3. `onFilterChanged` 只调了 `categoryWall.show()`，没切 `wallMode`，墙还是隐藏的 → 改走 `renderCategory()`。

### 5. 弹幕：不是源没有，是链断了

- 网盘源给的弹幕地址（`wexautodanmu`）返回空列表，回退内置库这条链本身也是断的；
- **集数被拼错**：旧代码把所有数字拼成一个数，`[5.0GB]E22.mkv` → 5022。改成按
  `S01E22 → E22 → 第22集 → [22] → 最后一个数` 识别，先摘体积/分辨率/编码/扩展名/年份；
- 按集搜索的响应里挂多家番剧，旧代码只看第一家 → 改成扫描全部 `animes`；
- 解析时按当前播放位置过滤，整批弹幕都在位置之前会被判成「0 条 → 加载失败」→ 兜底取全量；
- 内置接口走全站 DoH，实机 15~20s 超时 → 弹幕接口单独用系统 DNS，实测 1.2s。

## 三、交互

### 1. 返回键按视觉层级逐层退

统一 `BackTop`：**焦点不在顶栏，返回只把焦点收回顶栏/操作行；已经在最外层，这一次才关模块页。**

| 页面 | 层级 |
|---|---|
| 音乐 | 列表 → 「播放全部」 → 顶栏页签 |
| 哔哩哔哩 | 卡片墙 → 子页签（换一批/刷新）→ 顶栏页签 |
| 应用 | 卡片墙 → 顶栏页签 |
| 桌面 / 设置 / 信号源 | 内容 → 顶栏 |

隐藏的层会自动跳过，动作没落上焦点就继续往上，绝不吞掉返回键却什么都不做。

### 2. 搜索页

- 搜索结果分批到达时不再重建整面墙，焦点不再跳回片名框；
- 结果卡恢复 3dp 白色焦点框（之前只靠 1.06 放大，一屏十几张几乎一样大）。

## 四、音源市场

### 1. 为什么一直不同步上游

上游（`guoyue2010/lxmusic-`）早就只发 **Releases**（每个 tag 一个 zip），
仓库 `main` 里的版本目录停在 `V260907`。我们读的是仓库目录树，所以市场永远只有那 18 个音源。

现在读 `/releases/latest` → 下最新 zip → 列包里的 js，实测拿到 `V261104`（24 个音源）。

几个实机坑：

- 直链 `github.com/.../releases/download/...` 在多数网络下连不上 → 走 `ghfast.top` / `gh-proxy.com`，
  逐个校验字节数；`ghproxy.net` 会截断，被跳过；
- 字节数对上也不一定是有效包 → 下完先真解一遍，解不开换下一个镜像；
- 实机上 `ZipFile` 对这个包直接报 `MALFORMED[1]`（电脑上能开）→ 改用流式 `ZipInputStream`；
- 包内文件名是 GBK，UTF-8 扫不动会自动换 GBK 重扫。

### 2. 已装 / 更新

- 文件名里的版本号归一化后认作同一音源（墨澜 v2.3.0 → v2.3.5 也认得出已装）；
- 装新版时顺手删掉旧脚本，音源列表里不会并排两条同名条目；
- 行尾显示「已装 · 覆盖更新」/「下载」，副标题显示「24 个音源 · 上游 V261104 · 已装 N 个」。

### 3. 排版

- 内容压标题：`ListView` 的 `clipToPadding=false` 会让滚动的行画到自己边界之外，外层加裁剪盒；
- 行距：`AbsListView` 丢子项 margin，改用 `dividerHeight=10dp`；行高 72 → 84dp；
- 无封面时在占位底上显示版块字形（扫/市/云/装/♪），不再是一块空方块。
