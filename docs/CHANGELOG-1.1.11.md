# TVDesk 1.1.11

版本：1.1.11（versionCode 22）
日期：2026-11-07

主题：**桌面守护的判定收口** —— 按《桌面守护、安装与机型适配执行方案》的 M1 阶段做，
先把「什么时候该抢前台」这件事从一个入口一个说法，改成所有入口问同一个策略。

---

## 一、为什么先做这个

守护原来的判定散在三个地方：窗口事件里一套、亮屏复查里一套、连接后复查里又是另一套。
三处宽松程度不一样，用户看到的是「有时候把我拉回去、有时候不拉」——同一个场景，走哪条路
决定结果。更糟的是两条路会拿**旧标记**当证据：

- 亮屏复查直接读 `lastForeground`（上一次窗口事件留下的包名，可能是几分钟前的）；
- 连接复查用「强停前在不在桌面」放宽，那个标记是上一段时间的事实。

把旧事实当现在的前台，就会在用户已经打开别的应用时把桌面拉出来。

## 二、改了什么

### 统一判定（新增 `HomeTakeoverPolicy`）

所有入口给证据、拿结论：`ALLOW / DENY / RETRY` + 一句人能读的原因。判定顺序：

1. 守护开着吗 → 2. 临时放行中吗 → 3. 恢复熔断了吗 →
4. 屏幕可交互吗 → 5. 已经在前台吗 → 6. 前台未知吗（RETRY）→ 7. 是原厂桌面吗

RETRY 是这次新增的：以前「前台读不到」和「前台是别的应用」都归成「不抢」，
于是刚开机那几秒（还没画出窗口）永远不接管。现在前者会过一会儿再看，后者直接放弃。

这个类**不启动任何 Activity**，只做判断，将来可以直接单测。

### 进程内运行状态（新增 `GuardRuntimeState`）

记录本进程的代次、恢复次数、最近一次判定原因。关键的语义修正：
**「系统配置里写着这个服务」不等于「现在真的连上了」**——前者跨进程重启还残留，
后者只在 `onServiceConnected` 回调过之后才成立。

### 三个入口接线

| 入口 | 以前 | 现在 |
|---|---|---|
| 窗口事件 | 自己判 `isHomePackage` | 走策略 |
| 亮屏复查 | 用旧 `lastForeground` | 重新读实时前台，走策略 |
| 连接后复查 | 用 `wasHome` 旧标记放宽 | 走策略，前台未知就 RETRY |
| 复活闹钟 | **直接 `startActivity` 拉桌面** | 只补无障碍绑定，不抢前台 |

闹钟那条是这次最实际的一刀：它是周期性的，屏幕一亮就跑，根本不知道用户此刻在看视频、
进设置还是 HDMI。抢前台的判断交给手上有实时证据的无障碍服务。

### 恢复熔断

一轮恢复最多 4 次（2/5/15/30 秒的节奏），补不回来就停手等用户操作——不再每隔几分钟
写一次系统设置。

### 两个静默 bug

- **API 21/22 上「保持 ADB」永远不生效**：`context.checkSelfPermission` 是 API 23 才有的，
  5.x 上直接抛 `NoSuchMethod`，被 catch 吃掉变成「没授权」。改用
  `PackageManager.checkPermission`。
- **状态查询有副作用**：`notificationListenerReady()` 原本是
  `isEnabled() || ensureNotificationListener()`——**打开设置页看一眼状态，就顺手把通知监听
  权限开了**。现在只读，激活必须用户点确认。

### 默认值

`keepAdb` 默认从 `true` 改成 `false`。新装的用户没同意过「帮我把 ADB 一直开着」，
而且这会把调试口长期暴露在局域网里。已经手动开过的设备不受影响（值已存在）。

## 三、真机验证（小米 MiTV-MFTR0 / Android 14）

| 场景 | 结果 |
|---|---|
| 打开系统设置，静置 150 秒 | 仍在设置页，**没有被拉回桌面** |
| 从原厂桌面按 HOME | `接管 HOME：从 com.mitv.tvhome 回到桌面`，正常回到 TVDesk |

第一条是这次的重点：以前闹钟那一路会在屏幕亮起时无条件拉桌面，现在不会了。

## 四、还没做的（方案 M2–M5）

本轮只完成 M1。后续：

- **M2 分包**：standard / guard × java / java32 / java64 六个变体，清单里 guard 不含 HOME，
  更新器按模式选包。
- **M3 安装工具**：`tools/tvdesk-setup.ps1` / `.sh`，Detect / Install / Verify / Restore / Report。
- **M4 机型规则**：内置 `device-profiles.json` + 能力探测，先覆盖原生、小米、TCL。
- **M5 发布验收**：正式签名全量验收、真机矩阵记录。

## 五、已知边界

- 临时放行（`stockAllowed`）仍由「回到原桌面 / 从原桌面进应用」触发，没有强制时长上限；
  这一版没加，因为加了会影响现有的「去原厂设置找东西」流程，需要单独设计入口。
- 状态页还没做（方案 10.1 的「桌面接管状态」页面），当前只能从日志和设置页的卡片看。
