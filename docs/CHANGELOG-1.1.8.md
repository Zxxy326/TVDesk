# TVDesk 1.1.8

版本：1.1.8（versionCode 19）
日期：2026-11-06

主题：**首页改成背景墙** —— 去掉底部海报行，简介压到屏幕底部，影视也开始尝试播背景视频。

---

## 一、首页布局

| 项 | 以前 | 现在 |
|---|---|---|
| 底部海报行 | 铺一行海报，是主要的浏览入口 | **去掉**（`row_section` 常驻 GONE） |
| 信息块位置 | 屏幕上方 112dp 起 | **贴底**（`layout_gravity=bottom`，底边留 88dp） |
| 分页圆点 | 一排十几个点 | **去掉** |
| 简介 | 3 行 | **2 行** |
| 沉浸态标题 | 44sp | **34sp**（缩到 0.78 倍） |

首页现在一屏就是一条内容：整屏画面 + 左下角标题/简介/按钮，20 秒无操作进沉浸（按钮和顶栏收起）。

浏览入口变成顶栏页签（花卷电影 / 剧集 / 动漫…）、搜索、收藏页。海报墙还在，
但只在点页签进类目时出现。

## 二、影视也播背景视频

以前只有 B 站热门有视频，影视条目只有静态剧照。现在影视也走同一条链路：

1. 条目 → 详情接口拿剧集列表 → 取第一条线路的第一集；
2. 地址是直链（m3u8/mp4）就直接播，不是就交给爬虫 `playerContent` 解析一次；
3. m3u8 用 `HlsMediaSource`，mp4 用 `ProgressiveMediaSource`。

**首页那批是豆瓣条目，没有源站 id。** 所以多一步：拿片名去配置里第一个非网盘源搜一条，
**要求片名严格相等**才认（搜「庆余年」会回一堆「庆余年2」，配错就是「标题是这部、画面是那部」）。

### 时间是这么解决的

影视这条链路（搜源 + 详情 + 解析）要好 几秒，比 B 站的 0.5 秒慢一个量级。
所以：

- **预取**：换到某一条时，后台把**接下来两条**的地址解析好（`BackdropQueue.peek`），
  轮到的时候直接命中；
- **计时从「就绪」开始**：不再从换条那一刻算 8 秒，而是等首帧到了、或确定播不了
  （超时/竖屏/403）之后再开始计。否则准备 5 秒，画面只剩 3 秒；
- 首帧预算：B 站 3 秒，影视 6 秒（HLS 要下清单再下分片）。

## 三、竖屏与比例

- **竖屏视频不播**：拿到视频尺寸时先看 `height > width`，是竖的就回静态图。
  竖屏素材铺到 16:9 桌面上两边会裁掉一大半，只剩一条人像。
- **4:3 不再拉伸**：视频层外面套了 `AspectRatioFrameLayout`（zoom），按视频真实比例
  放大填满、裁掉多出来的一圈。以前 1440×1080 的投稿铺满 16:9 会横向拉宽，人像全变形。

## 四、停留 10 秒、每条露 2 秒标题

- 默认停留 **10 秒**（设置里仍是 6 / 8 / 10 / 15 四档）。
- **每换一条都先显示 2 秒标题/简介**，然后整块淡出，屏幕只剩画面。
  不是只在刚进沉浸时露一次——那样十条里有九条是「无名画面」。
- 沉浸态按**确定键**：退出沉浸、焦点直接落在「开始播放」上，**这一下不播放**，
  再按一下才起播。看纯画面时一按就起播会莫名其妙。
- 方向键/返回键照旧：退出沉浸并把焦点还回原处。

## 五、关于「不换源、直接用直连 m3u8 的源」

代码里已经做了：先按条目自己的源试，拿到的是 `127.0.0.1`（本地转发）就判定不合格，
再按片名去配置里的其它源挨个试，谁给真实 http 直链就用谁。

**但这套配置里做不到**：配置的 91 个源**全部是 type=3**（网盘聚合），
没有一个是直连站点。实测：

```
MovieBackdrop: 按片名找直连流：美人余，候选 91 个源
MovieBackdrop: 搜索失败 AiQwMkv：Value <!DOCTYPE of type java.lang.String ...
MovieBackdrop: 源 玩偶 超时/失败，跳过
```

大部分源搜索十几秒才失败、回的还是 HTML 错误页。所以：

- 单个源加了 **8 秒超时**（spider 的搜索是同步阻塞且不可中断，不设上限会把预取线程占满）；
- 连续 **3 条**拿不到直连流就整体放弃，本次运行不再试影视背景视频
  （否则每十秒白跑十几秒的网络请求）。

要影视也播视频，需要一个**带直连源的配置**（非 type=3 的站点），换配置重启即可，
代码不用改。

## 六、结果

这台电视上影视背景视频基本播不出来（只有静态图），B 站那 30% 正常。
要继续往前推，需要一个带直连源的配置——换配置重启即可，代码不用改。

## 七、已知未验

- 带直连源的配置下，影视视频的实际首帧耗时（只验到「解析成功、播放被 403 拒绝」）。
- 连续轮播 30 分钟的内存与温度。
