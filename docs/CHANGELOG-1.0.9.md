# TVDesk 1.0.9

版本：1.0.9（versionCode 10）
日期：2026-11-01

两件事：**更新弹窗换成软件自己的面板**、**更新检查改走加速站**（顺带修掉「弹窗根本不出现」的 bug）。

## 1. 更新弹窗改成软件风格

用户原话：「更新弹窗的窗口 UI 太古老了，更新成本软件风格」。

系统 `AlertDialog` 在电视上是白底方块 + 直角按钮，和整个界面（玻璃面板、圆角胶囊、聚焦放大）
完全是两个东西。现在和「返回桌面」确认框用同一套：

- `bg_dialog_panel`（深色玻璃、大圆角、细描边）+ 三颗 `bg_dialog_btn` 胶囊；
- 标题「发现新版本 1.0.9」+ 琥珀色副标题（当前版本 / 不会丢配置）；
- 更新说明单独一区，最多 260dp 高、超出可滚；
- 按钮：下载并安装（白底主按钮）/ 忽略此版本 / 以后再说，都带 1.04 聚焦放大；
- **下载态**：说明区换成琥珀色进度条 + 百分比，按钮隐藏，BACK 也不给关
  （关掉会留半个包，用户既不知道要不要等，也不知道重来会不会出问题）；
- 下载失败：退回可操作状态，把原因写进说明区。

## 2. 弹窗「根本不出现」（排查过程记一笔）

改完第一版，日志里明明拿到了新版本号、`newer=true`，屏幕上却什么都没有，而且**没有任何异常**。

两个坑：

1. 界面在 **构造函数** 里 `setContentView` —— Dialog 的窗口是 `show()` 之后才挂上的，
   塞进一个还没准备好的窗口，结果就是「不报错、也不显示」。改到 `onCreate` 里建。
2. `onCreate` 里 `(Activity) getContext()` —— Dialog 包了一层 `ContextThemeWrapper`，
   强转直接 ClassCastException，异常被 catch 后只打了一行日志。改成构造时把 Activity 存下来。

修完实测：设置 → 关于 → 检查更新，弹窗正常出现，面板、按钮、聚焦都对。

## 3. 更新检查改走加速站（这次是真的实时了）

1.0.8 把清单源换成了 jsDelivr 的 `@latest`，本来指望「tag 不可变、缓存不会错」。
实测发现 `@latest` 的 **alias 解析本身也有缓存**：发完 1.0.8，`@latest` 还在返回 1.0.7 的清单。

现在前两个源改成「加速站转发 raw」：

```
https://ghfast.top/https://raw.githubusercontent.com/Zxxy326/TVDesk/main/dist/update.json
https://gh-proxy.com/https://raw.githubusercontent.com/Zxxy326/TVDesk/main/dist/update.json
```

- raw 本身只有 5 分钟缓存，加速站是纯转发，**内容实时**；
- 国内直连可用（实测不带代理也能取到）；
- 仍然「所有源都问一遍、取版本号最大的」，某一个滞后不会被误判成「已是最新」；
- jsDelivr 的两条降到最后当兜底。

实测（电视，MiTV-MFTR0，无代理）：`ghfast.top -> 10`、`gh-proxy.com -> 10`，
拿到的就是当下这一版。
