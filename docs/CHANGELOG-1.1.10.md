# TVDesk 1.1.10

版本：1.1.10（versionCode 21）
日期：2026-11-06

主题：**修「开了背景声音还是没声音」**。

## 原因

B 站的播放接口返回的是 **DASH**：画面和声音是**两条独立的地址**
（`dashVideo` / `dashAudio`），要播放器自己合并。

背景墙从第一天起就只取了 `dashVideo`——

```java
if (stream.kind == BiliStream.DASH) {
    url = stream.dashVideo;   // 只有画面
}
```

当时默认静音，所以没人发现。这一版开了声音，B 站那部分就全露馅了：
抖音的 mp4 自带音轨，所以「有的有声音、有的没有」。

## 改法

- 取流结果从「一个 URL」改成「画面 + 可选音轨」（`Src`）；
- B 站 DASH 顺带取 `dashAudio`，用 `MergingMediaSource` 把两条源合并播放；
- **静音时不取音轨**：开着声音才请求，省一半流量；
- 抖音、影视的流本身就含音轨，构造 `Src` 时音频留空，照旧单源播。

## 实测

```
DeskBackdrop: 背景 2/12 B站 【假装讲电影】...
DeskBackdrop: 背景流 BV1ni4B6jE1c qn=80/80 audio=true ...
AudioTrack: setVolume() gain: 0.4
AudioTrack: [MITVLOG] start(175): prior state:STATE_STOPPED
```

`audio=true` 说明音轨带上了，`gain: 0.4` 正是设置里第 6 档（6/15）的音量，
`AudioTrack start` 说明音频轨真的在出声。

## 二、首页每次打开换一批

以前首页那三十条是固定的榜单（豆瓣四档第一页），开十次都是一样的。

现在：

- 每档随机挑一个**翻页起点**（`page_start` 取 0/20/40/60/80，实测每页内容都不同）；
- 每档取 20 条后**页内洗牌**，再留 8 条；
- 四档交错合并成 32 条。

实测两次冷启动，第一屏七张海报**一张都不重样**。

一个刻意的边界：**进程内只拉一次**。换批次发生在「打开电视」那一刻；
切页签回首页、进详情再返回，看到的还是同一批——否则刚看中的片子一转手就没了。

## 已知边界

- **没有申请音频焦点**：如果后台正在放音乐，屏保的声音会和它混在一起。
  需要的话下一版加「拿不到焦点就静音」。
- 影视条目仍然取不到流（网盘源 403），这条路径不受本次修改影响。
